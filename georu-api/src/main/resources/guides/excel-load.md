# 엑셀 이관 안내

담당자가 정리한 엑셀(xlsx·csv)을 TOBE 테이블에 적재하는 절차와 **파일 크기 기준**, **큰 파일을 나눠 올리는 방법**입니다. 화면은 [엑셀 이관](/ui/excel), 개발·API 상세는 저장소 `document/docs/EXCEL-LOAD-GUIDE.md` 입니다.

## 한눈에 보기

1. 화면에서 플러그인·테이블을 고르고 **템플릿 내려받기**.
2. `data` 시트 1행 헤더 아래에 값을 채운다. 노란 헤더는 필수.
3. **업로드** → 저장 직후 크기 확인과 검증(필수·길이·타입·PK 중복)이 돈다.
4. 목록에서 파일을 골라 **테스트 모드**(기본 WRITER_TEST)로 먼저 돌려 보고, 문제 없으면 **NORMAL** 로 적재.
5. NORMAL 이 끝나면 파일은 `completed`(성공) 또는 `failed`(실패) 폴더로 옮겨진다.

## 파일 크기 기준

| 항목 | 기준 | 넘으면 |
|---|---|---|
| 파일 크기 | **50MB 이하** (`spring.servlet.multipart.max-file-size`) | 화면이 업로드 전에 막고, API 는 413 `UPLOAD_TOO_LARGE` |
| xlsx 셀 수 (첫 시트, 행 × 열, 헤더 포함) | **50만 개 이하** (`georu.excel.xlsx-max-cells`) | 업로드 직후 거부 (`EXCEL_TOO_LARGE`) + 나누는 방법 안내 |
| xlsx 권장 셀 수 | **20만 개 이하** (`georu.excel.xlsx-recommended-cells`). 예: 50열 × 4,000행 | 받기는 하지만 검증 결과에 경고 |
| CSV | 셀 수 제한 없음 (파일 크기 상한만) | 한 줄씩 읽어 메모리를 쓰지 않는다 |
| Excel 형식 한계 | 1,048,576행, 16,384열, 셀당 32,767자 | Excel 자체 한계 |
| 셀 값 길이 | 타겟 컬럼 길이 이하 | 검증에서 차단 |
| 오류 목록 | 2,000건까지 보관 (`georu.excel.max-issues`) | 넘는 건은 건수만 센다 |
| 시험 적재 | WRITER_TEST 는 100건까지 | 테스트 모드 규칙 |

**왜 xlsx 에 셀 수 상한이 있나.** xlsx 는 읽을 때 파일 전체를 메모리에 올리고, 압축이 풀리면 파일 크기의 수십 배가 된다. 앱은 메모리가 부족하면 스스로 종료하도록 설정되어 있어(`-XX:+ExitOnOutOfMemoryError`), 큰 xlsx 하나로 **실행 중이던 다른 이관까지 멈출 수 있다**. 그래서 업로드 직후 첫 시트의 셀 수를 메모리를 거의 쓰지 않는 방식으로 먼저 세고, 상한을 넘으면 열지 않는다.

기본값은 앱 힙 약 2GB(컨테이너 3GB × 70%) 기준의 **추정값**이다. 운영 서버는 힙 크기에 맞춰 `georu.excel.xlsx-max-cells` 를 조정한다.

## 큰 파일 나눠 올리기

상한을 넘거나 넘을 것 같으면 **한 테이블을 행 범위로 나눠 파일 여러 개**로 올린다.

예: 데이터 2,500행 → `1~1,000행` 파일 1개, `1,001~2,000행` 파일 1개, `2,001~2,500행` 파일 1개.

1. **파일당 행 수 정하기.** 화면의 "큰 파일 나눠 올리기" 에 데이터 행 수와 열 수를 넣고 "계산" 을 누른다. 파일당 행 수 = 권장 셀 수 ÷ 열 수 (보기 좋은 수로 내림). 업로드가 크기 때문에 거부되면 같은 표가 자동으로 나온다.
2. **원본 나누기.** 범위대로 잘라 새 파일로 저장한다. **파일마다 1행 헤더를 그대로 둔다.** 헤더가 없으면 모든 컬럼이 "타겟에 없는 컬럼" 으로 처리된다.
3. **이름 붙이기.** 제안 이름처럼 순번과 범위를 붙인다. 예: `fb_grcode_01_1-1000.xlsx`, `fb_grcode_02_1001-2000.xlsx`.
4. **업로드.** 같은 플러그인·테이블을 고르고 하나씩 올린다. 각 파일이 `VALIDATED` 인지 확인한다.
5. **차례로 실행.** 첫 파일부터 하나씩 실행한다 (한 번에 한 이관만 돈다).
   - 첫 파일은 평소대로.
   - **두 번째 파일부터는 "기존 데이터가 있어도 적재"(`ignoreExistingData`)를 켠다.** 켜지 않으면 앞 파일이 넣은 데이터 때문에 NORMAL 이 "기존 데이터" 로 멈춘다. 화면은 같은 테이블에 적재된 파일이 있으면 이를 알려 준다.
6. **확인.** 목록의 "적재/건너뜀" 합계가 원본 행 수와 맞는지 본다.

주의할 점:

- **범위가 겹치지 않게** 나눈다. 검증은 파일 안의 PK 중복만 보고, 파일 사이 중복은 보지 않는다. 겹치면 두 번째 파일이 적재 오류(PK 중복)로 멈추거나, SKIP 이면 그 행을 건너뛴다.
- 시퀀스(채번) 컬럼은 파일마다 이어서 번호를 받는다. 파일 순서가 바뀌어도 번호가 겹치지는 않는다.
- 행이 아주 많으면 xlsx 대신 **CSV(UTF-8)** 로 저장하는 편이 낫다. CSV 는 셀 수 제한이 없고 파일 크기(50MB)만 본다. 50MB 를 넘으면 CSV 도 같은 방법으로 나눈다.
- `.xls`(구형)는 받지 않는다. 엑셀에서 xlsx 또는 CSV 로 다시 저장한다.

## 오류 행 처리

| 값 | 실행 전 | 실행 중 |
|---|---|---|
| STOP (기본) | 검증 차단이 있으면 실행하지 않음 | 오류가 나면 Job 실패 (이미 넣은 청크는 남음) |
| SKIP | 행 단위 차단은 건너뛰고 실행 (헤더 단위 차단은 실행 불가) | 오류 행만 건너뛰고 계속, 목록 기록 |

## 입력 규칙

- 첫 시트만 읽는다. 첫 번째 비어 있지 않은 행이 헤더다. 헤더 대소문자는 구분하지 않는다.
- 날짜·일시는 문자로: `yyyy-MM-dd`, `yyyyMMdd`, `yyyy-MM-dd HH:mm:ss`, `yyyyMMddHHmmss`. 엑셀 날짜 서식 셀은 `yyyy-MM-dd[ HH:mm:ss]` 로 읽는다.
- 숫자는 천 단위 구분 없이. 정수 컬럼에 소수가 오면 차단.
- 감사 컬럼(등록자·수정자·일시)과 시퀀스 컬럼은 비우면 실행 때 채운다. WRITER_TEST 는 등록자가 `MIG-TEST`.
- 모르는 헤더는 무시(경고)한다.
