# 텔레그램 알림 메시지 유형

텔레그램 알림은 모든 프로파일에서 켜져 있습니다(`georu.notification.telegram.enabled=true`). 봇 토큰과 채팅방은 환경변수 `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`(Docker 는 `docker/.env`) 로 넣습니다. **같은 내용이 UI 알림 화면에도 쌓이므로** 텔레그램이 없어도 놓치지 않습니다. 토큰이 비어 있으면 전송만 실패하고 로그에 남습니다.

메시지는 두 갈래에서 나옵니다. **제품 알림**(ProductNotifier, 이관 결과·차단)과 **진행 알림**(TelegramNotificationService, 시작·청크·실패·시스템). 아래 표의 "UI 종류" 는 알림 화면의 종류 열입니다.

## 한눈에

| 머리말 | 언제 | UI 종류 | 조치 |
|---|---|---|---|
| ✅ [완료] 테이블 | NORMAL·WRITER_TEST 가 정상 완료 (묶음 실행 중에는 생략, 끝에 요약 1회) | 테이블 결과 INFO | 없음. 건수 확인 |
| ⚠️ [완료(경고)] 테이블 | 완료했지만 실패·skip 행이 있거나 건수가 다름 | 테이블 결과 WARNING | 이력 상세의 실패 건수·경고 사유 |
| ❌ [실패] 테이블 | Step 실패 (Writer 오류·적재 대기 초과 등) | 테이블 결과 ERROR | 차단·실패 안내서 |
| ⚠️ [기존 데이터] 타겟에 기존 데이터가 있어 적재를 중단했습니다 | NORMAL 직전 타겟에 행이 있음 | 기존 데이터 WARNING | 수작업 정리 또는 UPSERT + ignoreExistingData |
| ⚠️ [기존 데이터] 무시하고 적재합니다 | ignoreExistingData=true 로 진행 | 기존 데이터 WARNING | 의도한 것인지 확인 |
| ⛔ [실행 전 점검] 차단 항목이 있어 적재하지 않았습니다 | 자동 점검에서 길이·NOT NULL·타입 차단 | 점검 차단 WARNING | 점검 보고서(상세 링크) → 매퍼·Processor 수정 |
| ⛔ [미완 코드] 원천(FROM)이 지정되지 않아 실행하지 않았습니다 | Source XML 이 `WHERE 1 = 0` | 미완 코드 WARNING | 개발자가 매핑 채운 뒤 재배포 |
| ✅/⚠️ [묶음 실행 요약] 제목 | 실행 목록이 끝났을 때 1회 | 묶음 요약 | 경고·실패·차단 테이블 목록 확인 |
| 🗓️ [스케줄] 등록·일시정지·재개·취소·종료 | cron 스케줄 상태가 바뀔 때 (등록·재개 알림에 "활성 스케줄이 있는 동안 테이블·시나리오 이관은 실행되지 않습니다") | 스케줄 INFO | 없음 |
| ⚠️ [스케줄] 이번 주기 건너뜀 | 주기가 왔는데 다른 이관이 실행 중 | 스케줄 WARNING | 다음 주기를 기다리거나 즉시 실행 |
| ⚠️ [스케줄] 재기동 복원 | 앱 기동 시 저장된 스케줄을 일시정지 상태로 복원 (스케줄별 놓친 주기 횟수·시각, 중단된 주기 수). 활성이던 것이 없고 정리할 것도 없으면 보내지 않음 | 스케줄 WARNING (원래 활성·중단 없으면 INFO) | 실행 현황에서 기록 확인 후 재개 |
| ❌ [스케줄] 주기 실행 실패 | 주기 실행이 Job 을 띄우지 못함 (실행 전 차단은 차단 알림으로 따로 감) | 스케줄 ERROR | 메시지의 코드·사유 확인 |
| 🎬 [시나리오 시작] 이름 | 시나리오 실행 시작 1회 (모드·단계·단위 수·실행자·그룹) | 시나리오 진행 INFO | 없음 |
| ✅/⚠️/❌/⛔/⏹️ [시나리오 N/M단계] 이름 · 단계명 | 시나리오 단계 하나가 끝날 때마다 (날짜 분할 단계도 단계당 1회). 결과·단위·처리 건수·다음 단계 | 시나리오 진행 INFO/WARNING/ERROR | 멈춤이면 이력·그룹 상세 |
| ℹ️ 배치 작업 시작 🚀 | 테이블 Job 시작 (총 건수·예상 청크·요청 파라미터) | 기타 INFO | 없음 |
| ⚡ 청크 처리 진행 | `georu.notification.progress.chunk-interval`(기본 10) 번째 청크마다와 마지막 청크 (묶음 실행 중에는 생략) | 기타 INFO | 느리면 시스템 자원 확인 |
| 🚨 마이그레이션 실패 | Step 안에서 예외 (작업 ID·테이블·모드·단계·오류 유형·메시지 500자) | 기타 ERROR | 차단·실패 안내서 |
| ⚠️ 데이터 부족 알림 | 총 건수가 0 이거나 청크가 한 번도 돌지 않음 | 기타 WARNING | 테넌트·기간 조건·소스 데이터 확인 |
| 🔌 DB 연결 오류 / 🔌 DB 연결 복구 | 헬스 모니터(1시간 주기)에서 연속 실패 N회(기본 3) / 복구 | 시스템 | DB·네트워크 확인. 운영저장소면 Job 실행 불가 |
| ⏰ 청크 처리 멈춤 | 실행 중인데 청크 진척이 오래 없음 | 시스템 WARNING | 타겟 DB 잠금·네트워크 확인 |
| 🖥️ JVM 상태 경고 | 메모리·GC 일시정지 과다 | 시스템 WARNING | 청크 크기·힙 설정 |
| ⚠️ 시스템 부하 감지 | 적응형 지연이 부하를 감지해 대기 시간을 늘림 | 기타 WARNING | 없음 (자동 조절) |

## 메시지 본문 예

### 테이블 결과

```
✅ [완료] tb_member

플러그인: hr.member
상태: COMPLETED (NORMAL)
소스 980 / 필터 0 / 처리 980
타겟 적재 전 0 → 후 980
소요: 0.3초

상세: http://…/ui/history?migrationId=…
🕒 2026-10-17 23:20:11
```
경고가 있으면 "경고 사유" 목록이, 실패면 "오류" 문구가 붙습니다. 건수 비교를 끈 테이블(1:N)은 "(건수 비교 제외 테이블)" 표시.

### 기존 데이터 차단

```
⚠️ [기존 데이터] 타겟에 기존 데이터가 있어 적재를 중단했습니다.

플러그인: hr.stats
• tb_stat_menu : 기존 720건 (마지막 샘플 실행 …)

조치 방법
 1) 수작업으로 데이터를 정리한 뒤 다시 실행 → 정리 안내서: http://…/ui/guide?name=manual-cleanup
 2) 쿼리가 UPSERT·IGNORE 방식이면 ignoreExistingData=true 로 다시 실행
🕒 …
```

### 실행 전 점검 차단

```
⛔ [실행 전 점검] 차단 항목이 있어 적재하지 않았습니다.

플러그인: hr.member
점검 ID: PC-20261017…

유형별 차단 건수
• LENGTH_EXCEEDED 12
• NOT_NULL_MISSING 3

테이블
• tb_member : 차단 2 · 경고 1

상세: http://…/ui/precheck?runId=…
차단을 무시하려면 ignorePrecheckErrors=true 로 다시 실행 (권장하지 않음)
```

### 묶음 실행 요약

```
⚠️ [묶음 실행 요약] 실행 목록 12개

전체 12 / 완료 10 / 경고 1 / 실패 0 / 차단 1
소스 합계 43,742 / 처리 합계 43,015
소요: 12.4초

경고·실패·차단 테이블
• tb_sequence : BLOCKED 기존 데이터 7건
• tb_post : COMPLETED(경고) 차이 3

상세: http://…/ui/history
```
묶음 실행 중에는 테이블마다 "완료" 를 보내지 않고 경고·실패·차단만 즉시 보냅니다. 끝나면 이 요약 1회.

### 시나리오 시작 · 단계 진행

시나리오 이관은 시작 1회, 단계마다 1회, 끝에 위 요약 1회를 보냅니다 (예: 단계 11개면 시작 1 + 단계 11 + 요약 1). 청크·구간 단위로는 보내지 않습니다. 끄려면 `georu.product.notice.scenario-step: false` (요약은 그대로).

```
✅ [시나리오 5/11단계] 전체 이관 · 로그인 로그 (월별)

hr.member.tb_member_login_log
결과: 전체 성공 · 단위 13/13 · 처리 10,000 · 소요 5초
다음: 6단계 게시판 (tb_board)

그룹: SCF-a816e3be
```
멈추는 단계는 "다음" 대신 `여기서 멈춤 - …` 이 붙고, 실행 전 차단은 `⛔` 와 사유가 붙습니다. 전송은 비동기라 단계가 1초 안에 연달아 끝나면 텔레그램에서 순서가 바뀌어 보일 수 있습니다 — 머리말의 `N/M단계` 로 읽고, 정확한 순서는 UI 알림 화면에서 봅니다.

## 설정

| 항목 | 값 |
|---|---|
| 켬/끔 | `georu.notification.telegram.enabled` (기본 true, 모든 프로파일) |
| 토큰·채팅방 | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 환경변수. Docker 는 `docker/.env` → compose 가 넘김 |
| 재시도 | 실패 시 3회 (`retry-attempts`), 타임아웃 30초 |
| 청크 진행 알림 간격 | `georu.notification.progress.chunk-interval` (기본 10청크마다), `notify-on-complete` (마지막 청크, 기본 true) |
| DB 연속 실패 알림 기준 | `georu.monitor.db-failure-alert-threshold` (기본 3) |
| 보내는 형식 | HTML parse_mode. 링크는 서버 주소 + UI 경로 |

## 받지 않을 때 보는 곳

1. 알림 화면에 같은 내용이 있는가 → 있으면 전송 문제, 없으면 알림 자체가 안 난 것.
2. 로그 `Failed to send Telegram message after 3 attempts` → 토큰·채팅방이 비었거나 틀림, 봇이 채팅방에 없음, 개인 채팅은 봇에게 먼저 말을 걸어야 함.
3. 묶음 실행 중 "완료" 가 안 오는 것은 정상(끝에 요약 1회). 시나리오는 단계 알림이 대신 옵니다(`georu.product.notice.scenario-step`).
