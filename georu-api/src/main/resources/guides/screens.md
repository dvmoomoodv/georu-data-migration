# 화면 설명

운영 UI 는 **로그인한 뒤**([로그인 · 접근 통제](/ui/guide?name=login)) 같은 서버의 `/api/**` 를 부릅니다. 오른쪽 위의 이름이 로그인한 사람이고 누르면 내 계정, 그 옆이 로그아웃입니다. 왼쪽 메뉴 맨 위 검색 칸에 이름을 치면 메뉴가 걸러지고(`/` 키), 오른쪽 위 **⟳**는 화면 새로고침(작성 중인 값이 있으면 확인), **? 도움말**은 지금 화면의 이 절을 오른쪽 서랍으로 엽니다(새 탭은 Ctrl/⌘ + 클릭). 실행 기록의 실행자는 로그인한 이름입니다 (로그인을 꺼 둔 환경에서만 오른쪽 위 **실행자** 칸이 보이고 그 이름이 실립니다). 그 옆 점은 단일 실행 게이트 상태(초록 유휴 · 노랑 실행 중)입니다.

**화면 공통 (0.0.1)**: 자주 쓰지 않는 기능 · 목록 행의 상세 · 참고 목록은 오른쪽 **패널**(본문을 덮고 딤 처리, 왼쪽 모서리를 끌어 폭 조절 · 화면마다 기억, Esc · 바깥을 누르면 닫힘), 최근 기록은 **최근 ▾**. 이 화면의 패널은 화면 오른쪽 가운데의 **탭 막대**에서 바로 엽니다 — 버튼마다 패널 하나, 같은 버튼을 다시 누르면 닫히고, 닫혀 있는 동안 새 내용이 생기면 버튼에 점이 찍힙니다(좁은 화면에서는 오른쪽 아래 가로 줄). 맨 아래 **도움말** 은 상단 **?** 와 같은 이 화면 설명입니다. 단계 · 모니터링 카드(생성기의 1. 파일 · 2. 설정, 테이블 이관 실행의 ① ~ ③, 시스템 · 대시보드의 지표 카드, 시나리오 설계 ① 기본 정보)는 **머리를 눌러 접을 수 있고** 접힌 상태는 화면마다 기억됩니다. 접힌 머리에는 한 줄 요약이 보이고, 접힌 동안 오류 · 경고 · DB DOWN 이 생기면 저절로 펼쳐집니다. 결과 · 진행 · 실행 전 확인 카드는 접히지 않습니다.

**메뉴 구성** (작업 순서 기준, 운영 환경에서도 같음. 단 이관 설계는 운영(prd)에서 숨김. 묶음 이름을 누르면 접기/펴기). 실제로 보이는 메뉴는 **내 권한**에 따릅니다 — 권한에 없는 메뉴는 숨고, 조회만인 메뉴는 실행 · 변경 버튼이 보이지 않습니다 ([로그인 · 접근 통제](/ui/guide?name=login))

| 묶음 | 화면 |
|---|---|
| 이관 설계 | 코드 생성 · 관계 분석 · 매핑 정의서 초안 (관리자만. 운영 prd · `georu.codegen.enabled=false` 면 숨김) |
| 실행 | 테이블 이관 실행 · 시나리오 이관 실행(시나리오 설계 포함) · 엑셀 이관 |
| 현황·결과 | 대시보드 · 실행 현황(스케줄 포함) · 이력 · 알림 |
| 점검·관리 | 실행 전 점검 · 시스템(운영 기록 정리 포함) · 로그 · 사용자 · 권한(총관리자만) |
| 개발 도구 | DDL 도구(테이블 · 자바 모델 · Processor · Writer 탭) · Swagger ↗(운영 프로파일은 꺼짐) · 서버 진단 ↗ |
| 도움말 | 시작하기 · 안내서 · 구조 설명 |

## project

**이관 진행.** 투입부터 종료까지의 **단계 · 할 일 · 체크리스트**를 팀이 같이 봅니다. 처음 열면 권장 단계(0 투입 준비 · 1 분석 · 2 개발 · 3 테스트 · 4 본 이관 · 5 종료, 임시 초안)로 채워집니다.
- 항목을 체크하면 체크한 사람(로그인 이름) · 시각이 남습니다. 메모 · 해제도 항목의 **기록**에 남습니다.
- 단계는 **필수** 항목이 모두 체크되면 완료, 하나라도 체크되면 진행 중입니다. 시작일 · 완료일은 체크 시각으로 정해집니다. **선택** 항목은 완료 판정에서 빠집니다.
- **엑셀 내려받기** 파일이 그대로 양식입니다 (둘째 시트에 작성 안내). 단계 순서 · 단계 이름 · 항목 · 필수 · 알아야 할 것 · 링크(`/ui/…` 또는 `guide:<안내서>`) · 담당 열을 고쳐 **엑셀 올리기** → 미리보기(추가 · 삭제 · 바뀜, 체크된 채 지워지는 항목) → 적용. 단계 이름과 항목이 같은 행은 체크 · 메모가 이어집니다.
- **권장 단계로 되돌리기**: 권장 단계에 없는 항목은 지워지고 같은 항목의 체크는 유지됩니다. 앱 하나에 체크리스트 하나이므로 다음 차수는 내려받아 보관한 뒤 되돌립니다.
- 자동 체크는 없습니다. 각 항목의 **화면 ↗ · 안내서 ↗** 로 가서 확인하고 사람이 체크합니다. 저장은 운영 저장소 `migration_checklist_item` · `migration_checklist_event` (V12).

## account

**내 계정.** 비밀번호 바꾸기(현재 · 새 비밀번호 8자 이상), 내 **권한**과 그 권한의 **유휴 잠금** 분(권한마다 총관리자가 정함). 처음 로그인했거나 비밀번호가 초기화된 상태면 다른 화면 대신 여기로 와서 먼저 바꿔야 합니다. 상단 바의 사용자 이름을 누르면 열립니다. 자세한 것은 [로그인 · 접근 통제](/ui/guide?name=login).
- 운영 UI 와 API 는 로그인한 사람만 씁니다. 볼 수 있는 메뉴와 실행 여부는 **권한**(관리자 · 실행자 · 조회자 등)이 정하고, 권한과 사용자는 총관리자가 관리합니다. 실행 기록의 **실행자**는 로그인한 이름으로 남습니다(헤더로 바꿀 수 없음).
- 스크립트 · 자동화는 같은 계정으로 HTTP Basic(`curl -u admin:…`). 비밀번호를 바꾸기 전에는 변경 API 만 됩니다.
- 로그인 5회 실패 → 15분 잠금. 일반 사용자는 관리자가 잠금을 풀거나 비밀번호를 초기화합니다. 총관리자 비밀번호를 잊었으면 서버에서 `GEORU_ADMIN_RESET_PASSWORD=true` 로 한 번 재기동 → 총관리자 계정이 지워지고 초기 설정 화면에서 다시 정합니다(다른 사용자 · 권한은 그대로). 재기동이 끝나면 환경 변수를 지웁니다.

## gen-code

**코드 생성.** TOBE 컬럼 정의(CSV · xlsx · xls)를 올리면 업체 적용 전 필수 파일을 zip 으로 만듭니다: 업체 기본 셋트(Application · application.yml · 공통 변환 · 감사 규칙 · 의존 경계 테스트), 업무구분마다 Strategy(`@GeoruPlugin`), 이관대상 테이블마다 Reader · Processor · Writer · DTO 2 · XML 2, 그리고 `APPLY.md` · `generation-report.csv`. 올린 파일은 저장하지 않습니다.
- **예제 양식 내려받기**(xlsx): 첫 시트의 예제 행을 지우고 채워 그대로 올립니다. 열 이름에 설명 메모, 이관대상 · Writer · PK 칸은 드롭다운, 둘째 시트에 작성 안내. 필수 열은 테이블명 · 컬럼명 · 타입 · 업무구분 · 이관대상, **Writer 열(BATCH · REUSE)은 이관대상 테이블마다** 고르고 비면 화면의 Writer 기본값. **업무 패키지 열**에 업무구분의 영문 이름을 미리 적을 수 있고, 비면 영문 그대로 · 사전(회원→member …) · 테이블 이름 접두어로 제안합니다("제안" 표시, 바꿀 수 있음). 테이블 단위 값은 첫 행에만 써도, 모든 행에 같게 써도 됩니다.
- 순서: 파일 올리기 → 업체 단어(예: `acme` → `com.georu.acme`) → 업무구분마다 패키지 이름(한글 값은 영문 소문자로) → **검사** → **zip 내려받기** → 저장소 루트에서 `unzip -n <zip> -d .`. 설정은 이 브라우저에 기억됩니다.
- **업체 규칙 파일**(선택, xlsx): 업체 단어 · 사전 · 감사 컬럼 · 명명 규칙을 적은 파일을 정의 파일과 함께 올리면 2. 설정 칸이 파일 값으로 채워집니다(화면에서 바꾼 값이 우선). 양식은 **규칙 양식 내려받기**, 지금 화면 값을 파일로 받으려면 **현재 규칙 내려받기**. 생성 zip 에 `rules.xlsx` 가 같이 들어가고 서버에는 남지 않습니다. 관계 분석 · 매핑 정의서 초안 화면도 같은 파일을 올립니다 ([안내서](/ui/guide?name=generator) "업체 규칙 파일").
- 원천 메타: **소스 DB 메타데이터**(기본, 소스 DataSource 의 테이블 정보) · **ASIS 정의 파일** · **쓰지 않음**(원천에 같은 이름 컬럼이 있다고 가정). 메타가 있으면 이름 일치 → 감사 컬럼 규칙 → 공통 컬럼 규칙(REG_DATE · REG_ID · UPT_DATE · UPT_ID · USE_YN · DEL_YN) 순으로 SELECT 를 채우고, 못 채운 컬럼은 `TODO ← ASIS ?`.
- 원천 테이블 열이 빈 테이블은 골격(`WHERE 1 = 0`)으로 만들어지고 실행 전 확인에서 막힙니다. 할 일 수와 위치는 검사 결과와 zip 의 `generation-report.csv` 에 있습니다.
- DB 종류 "자동"은 그 DataSource 에 접속해 판단합니다(접속 실패면 소스 oracle · 타겟 mysql 로 두고 경고). Writer 기본(BATCH · REUSE)은 [Writer 고르기](/ui/guide?name=writer-choice), "Reader · Writer 파일"은 기본이 만들지 않음(엔진 공용, 데모와 같은 모양)이고 "테이블마다 만듦"을 고르면 지금처럼 테이블마다 Reader · Writer 파일을 받습니다, 테이블마다 바꾸려면 정의 파일에 `Writer` 열.
- **적용 안내**(오른쪽 탭 막대, 검사가 통과하면 결과의 **적용 안내 보기**)는 zip 의 APPLY.md 와 같은 내용, 2. 설정 머리의 **최근 ▾** 는 운영 저장소 `migration_gen_run` 기록(실행자 · 파일 이름 · 결과 요약 · 그때의 설정)입니다. 설정이 있는 기록을 고르면 그 설정으로 폼이 다시 채워지고(브라우저 저장값은 그대로), 같은 파일을 다시 올리면 같은 zip 이 나옵니다. 관계 분석 · 매핑 정의서 초안 화면도 같습니다. 파일 크기 상한 `georu.codegen.max-file-size`(기본 20MB).
- **TOBE 컬럼 정의 열**:

  | 열 | | 내용 |
  |---|---|---|
  | 테이블명 · 컬럼명 · 타입 | 필수 | 물리 이름과 TOBE 자료형 (`VARCHAR(50)` 처럼 길이를 함께 써도 되고 길이 열에 따로 써도 됨) |
  | 업무구분 | 필수 | 업무 묶음 (회원 · 게시판 …). 값마다 패키지 · Strategy 하나 |
  | 업무 패키지 | 선택 | 업무구분의 영문 패키지 이름 (예: member). 비우면 영문 그대로 · 사전 · 테이블 접두어로 제안, 못 찾으면 2. 설정에서 넣음 |
  | 이관대상 | 필수 | Y 면 코드를 만들고 N 이면 만들지 않음 |
  | 원천 테이블 | 선택 | ASIS 원천 테이블. 있으면 Source SELECT 를 원천 메타로 채우고, 비면 골격(`WHERE 1 = 0`, 실행 전 확인에서 막힘) |
  | Writer | 선택 | 이관대상 테이블마다 BATCH(대량 · 빠름) 또는 REUSE(행마다 · 실패 행 확인). 비면 2. 설정의 기본값 ([고르는 기준](/ui/guide?name=writer-choice)) |
  | PK · Not Null · 길이 · 설명 | 선택 | PK 는 행 식별 · 정렬 · 필수값 검증, 설명은 주석에 씀 |

  모르는 열은 무시하므로 분석용 열이 많은 정의서도 그대로 올립니다.

## gen-relations

**관계 분석.** FK 가 걸려 있지 않은 테이블 구조 정의(CSV · xlsx · xls, ASIS · TOBE 어느 쪽이든)를 올리면 컬럼 이름으로 FK 관계를 추정해 분석용 xlsx 를 만듭니다. 올린 파일은 저장하지 않습니다.
- 규칙: 부모 PK 와 같은 이름 컬럼(N:1 HIGH, PK 가 같은 확장 테이블 1:1 MEDIUM) · 자기참조 `PARENT_X`/`UPPER_X`(MEDIUM) · 접두어 + 부모 단일키(MEDIUM) · 업체 명명 규칙(설정, MEDIUM). 자료형 불일치 · 감사 컬럼은 LOW. 복합 FK 의 일부만 쓰는 경로는 중복경로. 백업 · 임시 테이블(NEW · BAK · TEMP · OLD · 4자리 이상 숫자)은 뺍니다.
- **예제 양식 내려받기**(xlsx): 테이블 구조만(테이블명 · 컬럼명 · 타입 필수, PK · Not Null 선택). 컬럼은 테이블 안의 실제 순서대로.
- PK 는 정의서의 PK 열을 쓰고, 끄거나 없으면 첫 컬럼 · 앞쪽 NOT NULL 키형 컬럼으로 추정합니다.
- xlsx: **관계 목록**(복합키는 컬럼 쌍마다 한 행, 검토 결과 칸에 확정 · 제외 · 보류) · **테이블 요약**(PK · 부모 · 자식 수 · 적재 단계) · **적재 순서**(부모 → 자식 단계, 순환) · **원본 정의**(올린 정의 + PK · FK · FK상태) · **안내**. 적재 순서는 시나리오 단계를 짤 때 참고합니다.
- 화면에는 요약과 앞 300건을 보여 주고(상태 · 신뢰도 · 테이블로 거름), 전체는 xlsx 에 있습니다. 기록은 `migration_gen_run`(tool=RELATIONS).
- **결과 읽는 법**: **FK추정** = HIGH · MEDIUM, **검토필요** = LOW. xlsx 관계 목록의 **검토 결과** 칸에 확정 · 제외 · 보류를 적습니다. **중복경로**는 복합 FK 의 일부만 쓰는 경로로, 상위 경로 FK 를 권장합니다. **적재 순서**는 부모 → 자식 단계(같은 단계는 순서 무관), 순환은 2단계 적재나 관계 제외를 검토합니다. 추정이므로 업무 담당자 검토가 필요하고, 타겟에 물리 FK 를 걸지는 업무 판단입니다.
- **업체 규칙 파일**(선택): 올리면 2. 설정의 명명 규칙 · 감사 컬럼이 파일 값으로 채워지고(화면에서 바꾼 값이 우선), 결과 xlsx 에 "적용 규칙" 시트가 붙습니다. 서버에는 남지 않습니다.

## gen-mapping

**매핑 정의서 초안.** ASIS · TOBE 정의(+ 선택: ASIS · TOBE 공통코드 표)를 올리면 테이블 대응 · 컬럼 매칭 · 전환기준을 제안한 매핑 정의서 초안(xlsx)을 만듭니다. 작업자는 엑셀에서 이어서 작성합니다 (다시 올려 반영하지 않음). 올린 파일은 저장하지 않습니다.
- 칸마다 **양식** 버튼: TOBE 정의는 코드 생성과 같은 양식, ASIS 정의는 테이블 정의 양식, 코드표는 공통코드 양식.
- 테이블 대응: TOBE 정의의 원천 테이블 열(여럿이면 N:1 결합). 없으면 컬럼 이름 겹침(흔한 컬럼은 가볍게) + 테이블 이름 유사로 추정해 "추정 (확정 필요)", 못 찾으면 "ASIS 대응 확인 필요". 어떤 TOBE 와도 안 이어진 ASIS 테이블은 "TOBE 대상 미정", 백업 · 임시 이름은 "대상아님 (추정)".
- 컬럼 매칭: 같은 이름 → 접미어 정규화(CODE↔CD · NAME↔NM · DATE↔DT …) → 감사 컬럼 규칙 → 공통 컬럼. 자료형이 다르면 형변환 식, 원천 없는 공통 컬럼은 기본값, `_CD` · `_CODE` 컬럼은 공통코드 매핑 참조.
- xlsx: 작성안내 · **테이블 매핑 목록**(정의 행수 · 미작성 행수 · 작성률 수식) · **테이블 매핑 정의서**(좌 Source · 가운데 구분 드롭다운 · 전환기준 · 우 Target, 자동 제안 파란 글씨 · 채울 칸 노란 바탕) · **공통코드 매핑 정의서** · 참조_ASIS컬럼 · 참조_TOBE컬럼. 기록은 `migration_gen_run`(tool=MAPPING).
- 공통코드: 코드명이 2건 · 50% 이상 겹치는 TOBE 코드그룹, 코드명이 같은 코드끼리 대응합니다.
- 자동 제안은 모두 "의미 확인"이 필요합니다. 구분 드롭다운: 매핑 · 변환 · 코드 · 기본값 · 직접이관 · 결합 · 조건부이관 · 참조 · 신규 · 대상아님. 정의서가 정리되면 TOBE 정의의 원천 테이블 열을 채워 [코드 생성](/ui/gen-code)으로 기본 소스를 만듭니다.

## dashboard

**대시보드.** 실행/완료/실패 건수와 성공률, 시스템 부하(CPU·힙·스레드·커넥션 풀, 24시간 추이), 실행 중 작업, DB 상태, 최근 이력 8건, 최근 7일 요약 PDF/XLSX.

- DB 가 DOWN 이면 그 DB 를 쓰는 Job 은 대기합니다. 시스템 화면에서 원인을 봅니다.

## execute

**테이블 이관 실행 (테이블 단위).** 요청 폼은 `POST /api/migrate/table` 본문과 1:1 입니다.
- 폼은 **① 대상 → ② 모드 → ③ 조건 → ④ 실행 전 확인**(NORMAL 만) 네 단계입니다 (0.0.1). 아래 **실행 바**에 무엇을 어떤 모드로 실행하는지 한 줄로 보이고, NORMAL 을 고르면 실행 바와 실행 버튼이 빨간 **NORMAL 실행**으로 바뀝니다. 조건의 테넌트 · 기간 · 추가 속성 · 스케줄은 값을 넣으면 파란 테두리와 값이 보여 접힌 채로도 무엇이 켜졌는지 알 수 있습니다.
- 플러그인 → 테이블을 고르면 아래에 **미완 코드 현황**(TODO·원천 미지정)이 뜹니다. 원천 미지정(`WHERE 1 = 0`)은 실행이 차단됩니다.
- 모드 기본값은 **WRITER_TEST**(적재 100건, 등록자 MIG-TEST). 순서는 READER_TEST → PROCESSOR_TEST → WRITER_TEST → NORMAL.
- **테넌트** 5칸은 업체 값. 기본값 `DEFAULT` 를 그대로 두면 소스 조건이 맞지 않아 0건이 됩니다.
- **실행 전 확인**(NORMAL 만): 기존 데이터가 있으면 경고 후 중단, `ignoreExistingData` 는 쿼리가 UPSERT·IGNORE 일 때만.
- **기간 조건 / 날짜 분할**은 Source SQL 이 기간 컬럼을 바인딩한 테이블에서만 동작합니다. 날짜는 YYYYMMDD(종료일 포함)로 맞춰 보냅니다. 날짜 분할은 구간마다 Job 1개이고, **구간이 실패하면** 계속(기본)/멈춤을 고릅니다. 실행하면 오른쪽에 구간 n/m·성공·실패·미실행과 **중지 요청** 버튼이 나오고, 결과는 전체 성공 / 부분 성공 / 실패로 판정합니다.
- 왼쪽은 **실행 폼 / 실행 목록** 탭, 오른쪽 진행 현황은 스크롤해도 고정됩니다(좁은 화면에서는 위로 올라옵니다).
- **+ 목록 → 실행 목록 탭 → 목록 순서대로 실행**: 여러 테이블을 브라우저에서 순차 실행. 앞 Job 이 끝나야 다음을 보냅니다. FAILED 가 나오면 멈춥니다(뒤 테이블이 의존할 수 있음). 차단(BLOCKED)은 건너뛰고 계속합니다.
- **실행 목록 vs 시나리오 이관** (어느 쪽을 써야 할지 고르는 기준):

  | | 실행 목록 | 시나리오 이관 |
  |---|---|---|
  | 순서를 지키는 쪽 | 브라우저. 창을 닫거나 새로고침하면 다음 테이블이 나가지 않음 | 서버. 창과 무관하게 끝까지 |
  | 순서 저장 | 이 브라우저에만 | 정의로 운영 저장소에 저장, 공유·변경 이력 |
  | 실패·차단 | FAILED 멈춤, BLOCKED 건너뜀 | 기본 모두 멈춤, 단계별 플래그로 계속 가능 |
  | 날짜 분할·결과 | 항목별 Job 결과 | 단계 → 구간 한 그룹, 전체/부분 성공 판정과 횟수 |
  | 맞는 때 | 몇 개 테이블을 바로 돌려 볼 때 | 부모 → 자식 순서가 중요한 실제 이관·반복 실행 |

  목록을 그대로 시나리오로 옮기려면 **이 목록을 시나리오로 설계 →** 를 누릅니다(공통 테넌트·청크는 첫 항목 기준, 항목마다 다른 값은 단계 옵션으로). 목록은 그대로 남습니다.
- **JSON 붙여넣기 / JSON 복사 / curl 복사**: 요청을 저장해 두고 재사용합니다. 보낼 JSON 전체는 오른쪽 탭 막대의 **요청 JSON**(폼을 바꾸면 바로 바뀜), 진행 현황 머리의 **최근 실행 ▾** 는 최근 10건(고르면 이력 상세).
- 오른쪽 **진행 현황**: 청크 진행률, 소스·적재·실패·skip, 시퀀스 요약, 보고서 다운로드. 차단되면 사유·조치·안내서 링크.

## scenario

**시나리오 이관 실행.** 정의 파일(`resources/scenarios/*.json`)에 적힌 순서로 단계(테이블, 플러그인 무관) → 날짜 구간 → Job 을 서버가 하나씩 실행합니다. 시나리오 전체가 실행 1건이라 도중에 다른 이관은 거절(409)됩니다.
- 위 목록에서 시나리오를 고르면 단계 흐름도가 나옵니다. 정의 오류나 프로파일이 맞지 않으면 "불가" 아래 첫 이유 한 줄과 건수가 보이고(시나리오 JSON 의 `profiles` 에 없는 프로파일이면 불가), 누르면 오른쪽 **정의 오류** 패널에 단계별 이유 전체와 설계에서 고치기(배포 파일은 복제해서 고치기)가 나옵니다.
- **사전 확인**: 단계별 기존 건수·채번 컬럼·막는 것(기존 데이터·미완 코드·사용 중)·주의(계속 설정)를 한 번에 봅니다. 조회만 하고 아무것도 바꾸지 않습니다.
- **실패 시 멈춤이 기본**입니다: 구간이 실패하면 남은 구간을 내지 않고(onUnitFailure=STOP), 단계가 끝까지 성공하지 못하면 시나리오를 멈춥니다(onStepStop=STOP_ALL). 정의의 단계별 설정이나 화면의 선택으로 "계속" 을 줄 수 있고, 그런 단계는 실행 확인창에 따로 보입니다.
- **진행 현황**: 단계 카드가 초록(성공)·빨강(실패·차단)·파랑(실행 중)·회색(미실행)으로 바뀌고 카드 안 작은 칸이 구간입니다. 아래 표에 구간별 상태·건수·소요, **중지 요청**(지금 Job 이 끝나면 다음을 내지 않음). 머리의 **최근 실행 ▾** 에서 지난 실행을 고르면 그 그룹을 여기에 보여 줍니다.
- 제품은 타겟을 지우지 않습니다. 다시 돌리려면 수작업 정리 후 실행합니다.
- **시나리오 추가·수정**은 **시나리오 설계** 화면에서 합니다: 목록 위 **+ 새 시나리오 (설계)**, **파일 올리기**(JSON 을 설계기로), 사용자 정의 행의 **설계·편집**, 어떤 행이든 **복제**(배포 파일 정의를 바탕으로 새로 만들 때), **JSON**(내려받기). 저장은 운영 저장소(`migration_scenario_def`)에 들어가고 재기동 후에도 남습니다. 배포 파일 정의는 읽기 전용이고 같은 id 로는 저장할 수 없습니다.
- 삭제 버튼은 없습니다. 쓰지 않을 정의는 **사용 안 함**으로 두면 목록에 남되 실행되지 않습니다. 지우려면 DBA 가 운영 저장소에서 직접 삭제합니다.
- 테이블 이관 실행의 **실행 목록**과의 차이(순서를 지키는 쪽 · 창을 닫으면 · 실패 처리 · 결과)는 [테이블 이관 실행](/ui/guide?name=screens#execute) 절의 표를 봅니다. 실행 목록을 시나리오로 옮기려면 테이블 이관 실행 → 실행 목록 탭의 **이 목록을 시나리오로 설계**.
- 실행 폼의 "구간이 실패하면" · "단계가 끝까지 성공하지 못하면"은 시나리오 기본값만 바꿉니다. 정의의 단계별 덮어쓰기(단계의 onUnitFailure · onStepStop)는 그대로 적용됩니다.

## scenario-design

**시나리오 설계.** JSON 없이 화면에서 시나리오를 만들고 고칩니다. 테이블 이관 요청의 모든 값을 공통(시나리오 전체)과 단계(그 테이블만)에서 넣을 수 있습니다.
- **① 기본 정보**(두 칸): 시나리오(id 는 **자동 채번** `scn-001, scn-002…` - 기존 최대 번호 + 1, 저장 시 확정·변경 불가, 이름·설명·실행 프로파일 체크·기본 정책 2개)와 공통 요청 값(테넌트 5칸·청크·시간 윈도우·추가 속성 attribute1~25).
- **② 단계 설계** 3단: 왼쪽 **테이블 카탈로그**(플러그인별 테이블, 검색, 표식: `분할可` 기간 조건·날짜 분할 가능, `채번` 채번 컬럼, `차단` 원천 미지정, `TODO n` 미완 코드, `#n` 플러그인이 선언한 추천 순서) → 더블클릭 또는 끌어다 놓기로 단계 추가. 가운데 **단계 흐름**: 끌어서 순서 변경, ↑↓, ✕, **추천 순서로 정렬**(같은 플러그인 안에서만). 오른쪽 **단계 속성**: 설명, 날짜 분할(단위·기간·**구간 보기**), 기간 조건, 단계 정책, 이 단계만 다른 값(청크·시간 윈도우·테넌트), 채번(컬럼·정책·동기화), 실행 전 확인 옵션, 추가 속성, **건수 보기**(타겟 기존 건수). **적용**을 눌러야 단계에 반영됩니다. 단계에는 공통과 다른 값만 저장됩니다.
- **③ 검토·저장**: 단계 요약 표, 모드를 골라 **사전 확인**(저장 전에도 단계별 기존 데이터·막는 것·주의를 확인), 정의 JSON(읽기 전용·복사)과 **변경 이력**(그 시점 JSON 보기, 저장한 시나리오만)은 어느 탭에서든 오른쪽 탭 막대에서 엽니다.
- 위 버튼: **검증**(저장 없이 플러그인·테이블·정책·분할·값 범위 검사), **사전 확인**, **저장**(검증 통과 시만, 확인창), **저장 후 실행**(저장하고 시나리오 이관 실행 화면에서 사전 확인까지), **내려받기**.
- 보수 원칙: 저장은 검증 통과 시만, 삭제 없음(사용 안 함만), 실행은 시나리오 이관 실행 화면의 확인창을 거칩니다. 기존 건수는 보여 주기만 하고 지우지 않습니다.

## tables

**테이블 현황.** 모든 테이블의 매핑 상태(미완 코드 · 원천 미지정)와 마지막 실행 결과를 한 표로 봅니다. 미완 코드는 빌드할 때 스캔한 결과입니다(페이지 설명 옆 스캔 시각).
- 위 숫자 칸(테이블 · 실행 차단 · 미완 코드 남음 · 마지막 실행 완료 · 실패·차단 · 미실행)을 누르면 그 조건으로 걸러집니다. "테이블" 칸은 조건 지우기.
- 툴바: 테이블명 검색 · 플러그인 · 매핑 상태 · 마지막 실행 결과 · **어떤 모드의 실행을 마지막으로 볼지**(기본 NORMAL) · 테넌트. 둘째 줄의 **이관 상태**(수행 · 대기 · 이관 제외) 체크로 보일 상태를 고릅니다. 머리글을 누르면 정렬.
- 행의 **실행 · 점검 · 이력**은 그 테이블로 채워진 화면으로 갑니다. 대기 · 이관 제외 테이블은 실행할 수 없고, 이관 제외는 점검하지 않습니다.
- 상태(수행 · 대기 · 이관 제외)는 플러그인 코드의 `TableOptions.state` 로 정하며 화면에서 바꿀 수 없습니다. 차단 · 미완 건수와 "미완 위치 모아 보기"는 수행 테이블만 셉니다.
- **미완 위치 모아 보기**: 지금 보이는(걸러진) 수행 테이블 중 미완이 남은 테이블의 위치(file:line)를 오른쪽 패널에 한 목록으로 모읍니다. 유형 · 검색으로 거르고 **위치 복사**(탭 구분, 엑셀에 붙여 넣기). 목록 조건을 바꾸면 패널을 닫고 다시 모읍니다. 매핑 칸을 누르면 그 테이블의 미완 상세.
- **목록 복사**: 지금 보이는 목록을 탭으로 구분해 복사합니다.

## running

**실행 현황.** 실행 중인 그룹(날짜 분할·시나리오, n/m 단위, 중지 요청), 실행 게이트(지금 무엇이 돌고 있나, 요청자, 경과), 실행 중 Job(청크 상세·중지), 등록된 스케줄(상태 활성·일시정지·종료와 사유, 마지막 주기 결과, 일시정지·재개·전체 일시정지·전체 재개, 등록 JSON, 주기 기록, 즉시 실행, 취소). 활성 스케줄이 있으면 테이블·시나리오 이관이 막히므로 이관 전에 전체 일시정지합니다. 스케줄은 운영 저장소에 저장되고, 앱을 재기동하면 일시정지 상태로 복원됩니다(배너 표시). "기록" 에서 놓친 주기·중단된 주기를 확인한 뒤 재개합니다.
- 실행 중 Job 의 진행 막대는 처리 건수 / 예상 전체 건수(직전 완료 실행의 원천 건수 또는 테스트 상한)이고, 예상 전체 건수를 모르면 흐르는 막대와 처리 건수만 보입니다.
- 게이트가 풀리지 않을 때만 **수동 해제**를 씁니다 (`POST /api/migrate/gate/release`).

## history

**이력.** migration_jobs 기준. **구분** 열이 테이블 / 시나리오(SCF-) / 날짜 분할(DIV-) / 실행 목록을 나누고 그룹 ID 를 함께 보여 줍니다. 기간·플러그인·테이블·상태·구분·모드·실행자로 걸러 보고("표시 열"로 테넌트·종료·skip·실행자·요청 열을 숨길 수 있음, 브라우저 저장), 행을 누르면 오른쪽 **상세 패널**(실행 흐름: 시작 → 실행 전 확인 → 청크 → 완료 판정 → 종료, Step 카운트·청크·실패 청크 재시도·로그·요청 JSON, 위 **↑ 이전 · 다음 ↓** 으로 목록의 앞뒤 행). 시나리오 실행은 JSON 버튼·상세에 **시나리오 전체 JSON**(실행 당시 정의 + 실행 요청)과 이 Job 의 단계·구간, 그 단위의 테이블 요청 JSON 이 함께 나옵니다. 보고서 CSV/XLSX/PDF 와 zip 내보내기(로그·청크 포함)는 오른쪽 탭 막대의 **보고서**(목록 조건 적용, 아래에 최근 zip 10개가 파일 목록으로 - 조건 · 상태 · 진행 · 크기 · 요청 시각, 다운로드 · 삭제 아이콘), **이 조건으로 다시 실행**(폼에 채우기만 함). 실행자 이름 앞의 동그라미는 이름 첫 글자입니다(같은 이름은 같은 색).
- 상태 COMPLETED 옆 "경고"는 일부 실패·skip 이 있다는 뜻입니다. 상세의 실패 건수와 로그를 봅니다.
- 오른쪽 탭 막대의 **실행 그룹**: 날짜 분할(DIV-)·시나리오(SCF-) 실행의 판정(전체 성공/부분 성공/실패/차단/중지)과 성공·실패·차단·미실행 횟수, 누르면 단위 표.

## precheck

**실행 전 점검.** 플러그인·테이블을 고르고 돌리면 소스 샘플(기본 1,000건)을 Processor 까지 변환해 타겟 컬럼 정의(길이·NOT NULL·타입·PK 중복)와 대조합니다. 타겟 · 소스 어디에도 쓰지 않습니다 (INSERT 는 문장만 만들고 실행하지 않음 — 결과의 "접속 기록" · "실행하지 않은 INSERT 문"). Processor 는 **점검 전용 객체**로 돌려 실행 중인 이관과 상태(채번 · 참조)를 나누지 않고, 변환이 시간 제한 안에 안 끝나면 경고만 남깁니다. 체크박스로 **타겟만 (ASIS 무접속)** · 소스만 · 둘 다를 고릅니다. 결과는 보고서로 내려받고 이력의 차단 패널에서도 열립니다. 지난 점검은 결과 머리의 **최근 점검**(패널, 고르면 본문에 결과)으로 엽니다. 아직 결과를 열지 않았으면 결과 칸에 가장 최근 점검 한 건이 색 타일(점검한 테이블 · 통과 · 경고 · 차단 테이블 수, 아래 줄에 경고 · 차단 항목 수)로 보이고 진행 중이면 5초마다 갱신됩니다. **결과 열기**로 테이블별 결과를 엽니다. 점검 흐름 · 쓰지 않는 근거 표 · NORMAL 실행 전 확인 · 점검 기준은 이 서랍(**? 도움말**) 위쪽에 있습니다.
- 적재하지 않습니다. 같은 테이블이 이관 중이면 점검을 거절합니다.
- NORMAL 실행 직전 자동 점검(`georu.precheck.auto-enabled`, **기본 켜짐**)이 같은 점검을 실행마다 돌립니다. 테이블 실행 · 시나리오 · 실행 목록 · 이력 상세에 "자동 점검" 배지(실행 직전 · 건너뜀 · 꺼짐 · 해당 없음)가 보입니다.

## excel

**엑셀 이관.** 담당자가 정리한 엑셀(xlsx·csv, 헤더 = TOBE 테이블 컬럼명)을 업로드해 테이블 이관 파이프라인으로 적재합니다. 플러그인·테이블을 고르고 템플릿을 내려받아 채운 뒤 업로드하면 즉시 검증(헤더 대조·필수·길이·타입·PK 중복)됩니다. 파일 목록에는 결과 메시지가 한 줄로 보이고, 행을 누르면 오른쪽 **파일 상세** 패널에 검증 결과 · 건너뛴 행 · 미리보기 · 재검증 · 삭제가 나옵니다. 파일을 고른 뒤 테스트 모드·오류 행 처리를 골라 실행하면 `POST /api/migrate/table` 에 `source=EXCEL, excelFileId` 로 요청됩니다.
- 적재는 해당 테이블의 Target 매퍼 쿼리(insertData)를 그대로 씁니다. 시퀀스 채번·감사 컬럼(등록자·일시)·기존 데이터 확인·게이트·이력·알림도 테이블 이관과 같습니다.
- 오류 행 처리 STOP(기본): 검증 차단이 있으면 실행하지 않고, 실행 중 오류는 Job 실패. SKIP: 오류 행만 건너뛰고 적재하며 목록을 남깁니다. 필수 컬럼이 없는 등 헤더 수준 차단은 SKIP 이어도 실행하지 않습니다.
- NORMAL 로 끝나면 파일은 `completed/`(성공) 또는 `failed/`(실패) 폴더로 옮겨지고 다시 실행할 수 없습니다 (다시 업로드). 테스트 모드는 파일을 옮기지 않습니다.
- 크기 제한: 파일 50MB, xlsx 셀(행×열) 50만 개(권장 20만 개). 화면이 업로드 전에 파일 크기를 확인하고, 서버는 업로드 직후 xlsx 셀 수를 세어 넘으면 받지 않는다. 넘으면 오른쪽 탭 막대의 **나눠 올리기** 계산기(크기 초과로 업로드가 거절되면 자동으로 열림)로 한 테이블을 행 범위별 파일 여러 개로 나눠 올린다(두 번째 파일부터 "기존 데이터가 있어도 적재"). 상세: [엑셀 이관 안내서](/ui/guide?name=excel-load).
- 파일 폴더 `georu.excel.dir`(컨테이너 /app/data/excel), 대장은 운영 저장소 `migration_excel_file`. 안내: `document/docs/EXCEL-LOAD-GUIDE.md`.
- 형식: 헤더는 타겟 컬럼명(대소문자 무관). 날짜는 문자(yyyy-MM-dd 또는 yyyyMMdd), 숫자는 천 단위 구분 없이. **컬럼 대응표**(타겟 컬럼 ↔ DTO, 필수 · 감사 · 채번 컬럼)와 파일 **미리보기**(앞 20행 + 대응표)는 오른쪽 패널로 열립니다.

## notifications

**알림.** 텔레그램과 같은 내용이 쌓입니다: 테이블 결과, 묶음 요약, 기존 데이터 차단, 점검 차단, 미완 코드 차단, 시스템 상태. 검색·레벨·종류·기간으로 걸러 보고, 목록에는 제목 · 종류 · 테이블과 메시지 한 줄(넘치면 …)이 보이고, 알림을 누르면 오른쪽 **알림 내용** 패널에 전문(시각 · 종류 · 테이블 · migrationId · 이력 보기 · 조치 안내)이 나오면서 그 알림이 **읽음**으로 바뀌고 메뉴 · 상단 종의 배지 수가 내려갑니다(빨간 점 = 읽지 않음). 패널 위 **↑ 이전 · 다음 ↓** 으로 앞뒤 알림. **모두 읽음**은 한 번에 처리. 읽음 상태는 브라우저에만 저장됩니다. 종류 옆 "조치" 링크는 사유별 조치 안내서, 상단 "메시지 유형" 은 텔레그램 알림 안내서로 갑니다.

## system

**시스템.** 헬스 live/ready, DB·커넥션 풀, 플러그인 목록(위에 요약 칩 플러그인 · 활성 · 비활성 · 오류 · 업무, 지원 테이블 수, 미완 코드 집계 버튼), 성능 지표 추이, 오른쪽 탭 막대의 **기록 정리**(운영 기록 정리: 대상·기준일을 골라 건수 보기 → 확인 문구 입력 후 정리. 자동으로는 지우지 않음) · **성능 지표 (원본)**(지표 JSON).
- 플러그인이 안 보이면 `georu.plugins.<name>.enabled` 와 데이터소스 토글 조합을 봅니다.
- 더 자세한 진단(스레드 덤프, JVM·GC, 지표 탐색)은 **개발 도구 › 서버 진단**(새 탭)으로 봅니다.

## users

**사용자 관리** (총관리자만, 메뉴 점검·관리 › 사용자 · 권한). 사용자 목록(권한 · 상태 · 마지막 로그인)과 오른쪽의 추가 · 고치기 칸.
- **추가**: 아이디 · 이름 · 권한 · 초기 비밀번호(관리자가 정함). 사용자는 첫 로그인 때 바꿔야 합니다.
- 행마다 **작업** 열의 아이콘 버튼 **고치기**(연필, 이름 · 권한) · **비밀번호 초기화**(열쇠) · **잠금 풀기**(자물쇠, 잠겼을 때) · **삭제**(휴지통)와 글자 버튼 **사용 중지 / 다시 사용**. 아이콘에 마우스를 올리면 이름이 보입니다. 바꾸면 그 사용자의 다음 요청부터 적용됩니다.
- 총관리자 행은 바꿀 수 없습니다 (비밀번호는 내 계정에서). 관리자 권한은 고를 수 없습니다.
- 관리자가 정한 초기 비밀번호는 첫 로그인 때 바꿔야 다른 화면을 씁니다. 사용 중지 · 삭제면 그 사용자는 바로 로그아웃됩니다.
- 사용자를 지워도 실행 기록의 실행자 이름은 그대로 남습니다. 잠깐 막기만 하려면 **사용 중지**. 자세한 것은 [로그인 · 접근 통제](/ui/guide?name=login).

## roles

**권한 관리** (총관리자만, 사용자 · 권한의 **권한** 탭). 권한 목록(메뉴 요약 · 유휴 잠금 · 사용자 수)과 추가 · 고치기. 행의 **작업** 열은 고치기(연필) · 삭제(휴지통) 아이콘입니다.
- 메뉴 표에서 메뉴마다 **없음 / 조회 / 실행**. "기본 권한에서 복사" 로 실행자 · 조회자 값에서 시작합니다.
- 관리자 권한은 유휴 잠금 시간만 바꿀 수 있습니다.
- **삭제**는 그 권한의 사용자도 함께 지웁니다 (확인 창에 사용자 목록, 권한 이름 입력).

## logs

**로그.** 파일 로그 검색(레벨·낱말). 툴바의 **파일 ▾** 를 누르면 로그 파일 목록 패널(이름 · 크기 · 수정 시각, 지금 파일은 색으로 표시)이 열리고, 고르면 그 파일로 다시 조회합니다. 메시지는 한 줄(넘치면 …)로 보이고 여러 줄(스택)이면 **+N줄** 이 붙습니다. 줄을 누르면 오른쪽 **로그 줄** 패널에 로거 · 스레드 · 메시지 전체(스택도 칸 안에서 여러 줄로)와 복사 · 이 실행 이력 · 이 migrationId 로 검색. 이력 상세의 로그 탭은 그 실행의 로그만 보여 줍니다.
- 이 화면은 컨테이너의 `/app/logs` 파일(로컬은 `docker/volumes/logs`)을 직접 읽습니다. DB 테이블이 아닙니다. 이관 작업별 진행 기록은 운영 저장소 `migration_logs` 에 있고 [이력](/ui/history) 상세의 "작업 로그"에서 봅니다.
- 파일: application.log 앱 로그 · sql.log SQL 로그 · gc.log GC 로그(형식 없음, 줄 그대로). 날짜가 붙은 파일은 지난 날짜분.

## guide

**안내서.** 왼쪽 목차(시작·운영·개발)에서 고르고, 위 검색 칸으로 모든 안내서를 한 번에 찾습니다. 제목에 마우스를 올리면 `#` 앵커가 보여 특정 절을 링크할 수 있습니다. **원문 (Markdown)** 버튼은 파일 그대로.

## architecture

**구조 설명.** Reader·Processor·Writer·Strategy·Plugin 등 핵심 클래스와 구조도, 테이블 하나가 옮겨지는 8단계. 페이지 머리의 **목차**는 구성 요소 목록 패널(누르면 그 설명으로 이동).

## start

**시작하기.** 처음 쓰는 사람을 위한 한 장입니다.
- **1. 이 프로그램은**: 무엇을 하는 도구인지와 지키는 원칙(타겟을 지우지 않음 · 한 번에 한 이관 · 사람이 화면에서 실행).
- **2. 처음 10분**: 시스템에서 플러그인 · DB 확인 → 테이블 하나를 시험 모드로 실행 → 결과 확인 → NORMAL → 이력 순서. 앱이 예제 안내서를 더했다면 아래에 함께 나옵니다.
- **3. 화면 투어**: 메뉴마다 무엇을 하고 처음에 무엇을 보면 되는지. 처음에는 시스템 → 테이블 이관 실행 → 이력 세 화면만 보면 됩니다.
- **4. 다음에 읽을 것**: 운영 · 개발 안내서 링크. 화면마다 오른쪽 위 **? 도움말** 을 누르면 그 화면의 설명이 오른쪽 서랍으로 열립니다.

## ddl

**DDL → 테이블.** CREATE TABLE 문을 붙여 넣으면 컬럼 정의 표(타입 원문·타입·길이·소수·단위·NOT NULL·기본값·PK·UNIQUE·FK·자동증가·설명)로. 엑셀용(탭) 복사·Markdown 복사. 브라우저에서만 처리. DDL 도구 네 탭 모두 입력 칸 아래 **예제 ▾** 로 예제를 골라 넣고 바로 만들며, 읽는 구문 · 타입 규칙 · 관련 규칙 링크는 **? 도움말** 서랍에 있습니다.
- 읽는 것: CREATE TABLE(컬럼 · 제약 · MySQL COMMENT), COMMENT ON, ALTER TABLE ADD, CREATE INDEX, sp_addextendedproperty. Ctrl+Enter 로 변환. 관련 규칙: [매핑 규칙 카탈로그](/ui/guide?name=mapping-patterns).

## ddl-model

**DDL → 자바 모델.** 같은 DDL 로 Source/Target DTO 클래스. 타입 규칙은 생성기와 같습니다.
- 타입 규칙: NUMBER(p,0) p≤9 Integer · ≤18 Long · 그 외 BigDecimal, DATE → LocalDateTime, CLOB → String, RAW/BLOB → byte[], MySQL INT → Integer · BIGINT → Long · DECIMAL(p,0) ≤18 Long. 관련 규칙: [매핑 규칙 카탈로그 A](/ui/guide?name=mapping-patterns).

## ddl-processor

**DDL → Processor.** TOBE DDL 만 넣으면 같은 이름으로 복사하는 Processor, ASIS DDL 을 더 넣으면 이름이 다른 컬럼까지 매핑 추정. 표에서 원천·규칙을 고치면 Processor·transformItem·Source SELECT 초안·Strategy 옵션이 다시 생성됩니다. 규칙 근거는 매핑 규칙 카탈로그.
- 프레임워크 규칙: Source 매퍼 SELECT 가 TOBE 컬럼명으로 별칭을 주므로 Processor 는 보통 같은 이름으로 옮겨 담고, Java 후처리(코드 변환 · 경로 · 채번)만 규칙으로 더합니다.

## ddl-writer

**DDL → Writer.** TOBE DDL 로 Target 매퍼 INSERT · INSERT IGNORE · UPSERT · UPDATE XML 과 인터페이스. 키 컬럼·등록 전용 컬럼·foreach 선택. 제품은 지우지 않으므로 재실행이 필요하면 UPSERT/IGNORE + `ignoreExistingData=true`.
- 테이블이 여럿이거나 업체 적용을 시작한다면 **이관 설계 › 코드 생성**(켜져 있을 때)을 씁니다. TOBE 컬럼 정의 파일 하나로 업무 Strategy · 테이블별 Reader · Processor · Writer · DTO · XML 과 적용 안내까지 만듭니다. 이 탭은 DDL 하나로 Target XML 만 빠르게 볼 때. 관련 규칙: [매핑 규칙 카탈로그 H1](/ui/guide?name=mapping-patterns).

## admin

**서버 진단 (개발 도구 › 서버 진단 ↗).** Spring Boot Admin 화면(`/admin`)을 새 탭으로 엽니다. 개발·기술 지원용 진단 도구입니다. 테이블 이관 실행·중지는 하지 않습니다.
- **스레드 덤프:** Job 이 멈춘 것처럼 보일 때 Reader·Writer 스레드가 어디서 기다리는지(DB 락, 큐 대기) 봅니다.
- **Info (첫 화면):** 빌드 버전·시각, 켜진 플러그인·DataSource, 운영 저장소 종류, 시퀀스·청크 지연 설정. "이 서버가 어떤 설정으로 떠 있나"를 봅니다.
- **Health:** 운영 저장소·Oracle·MySQL 각각의 UP/DOWN.
- **Metrics:** 이관 지표 `migration.*` — 게이트 사용 중, 실행 중 Job, 큐 적재 대기, 테이블별 처리 건수·Job 소요 시간·청크 시간·실패 청크. JVM·GC·커넥션 풀 지표도 함께.
- **Logfile:** `application.log` 를 실시간으로 따라 봅니다(운영 UI 로그 화면은 검색·필터용).
- **설정값·로그 레벨:** docker·dev 프로파일만. 설정값은 이름만 보이고 값은 가려집니다.
- 메뉴가 없으면 `georu.admin-console.enabled`(환경변수 `APP_ADMIN_CONSOLE_ENABLED`)가 false 입니다. 바꾸면 재기동해야 합니다.
- 힙 덤프는 보안상 모든 환경에서 꺼져 있습니다.
