# 재실행·증분 절차

> 제품은 타겟을 지우지 않습니다. 재실행은 "정리는 사람이, 적재 방식은 Target XML 이" 정합니다.

## 다시 돌리기 (전량)

1. 타겟에 이미 행이 있으면 NORMAL 은 **기존 데이터 차단**으로 멈춥니다. 정상입니다.
2. 적재 쿼리가 일반 INSERT 면: 수작업 정리 안내서대로 백업 → 자식 테이블부터 정리 → 재실행.
3. 적재 쿼리가 UPSERT(`ON DUPLICATE KEY UPDATE`) 또는 `INSERT IGNORE` 면: 정리 없이 **기존 데이터가 있어도 적재**(ignoreExistingData) 를 켜고 재실행. 중복은 갱신 또는 건너뜀.
4. 채번 컬럼이 있는 테이블은 재실행하면 **새 번호**를 받습니다. 자식이 참조하는 키라면 자식도 다시 돌려야 합니다(매핑 규칙 C2·C3). 번호를 유지하는 테이블(동기화만)은 영향 없음.
5. 개발 환경(예제 앱)은 MySQL 초기화 도구 SQL 로 비울 수 있습니다. 제품 기능이 아닙니다.

## 적재 자동 재시도 (설정 없이 동작)

- 적재 1회(Writer 스레드가 한 번에 넣는 묶음, 최대 5,000건)가 **데드락·잠금 대기·시간 초과·연결 끊김**으로 실패하면 5초 → 10초 → 15초 뒤 최대 3번 다시 넣습니다. 성공하면 다음 묶음은 다시 3번까지 시도합니다.
- 묶음은 한 트랜잭션이라 실패하면 통째로 되돌려지므로 다시 넣어도 중복이 없습니다. 연결 끊김은 commit 여부를 모르므로 **타겟에 이미 있는 키를 걸러서** 다시 넣습니다(PK 가 없는 테이블은 재시도하지 않음).
- 제약 위반·길이 초과·NULL 같은 데이터 문제는 다시 해도 같으므로 재시도하지 않습니다.
- 재시도 끝에 성공하면 실행은 **완료(경고)** 로 끝나고 경고 사유에 "적재 재시도 끝에 성공 N회" 가 남습니다.
- 3번 모두 실패하면 실행은 FAILED 로 멈춥니다(남은 행을 계속 넣지 않음). 날짜 분할·시나리오는 실패 처리 설정(`onUnitFailure` 기본 STOP, `onStepStop` 기본 STOP_ALL)을 따릅니다.
- 끄려면 `georu.batch.queue.write-retry-max-attempts: 0`.

## 일부만 다시 (빠진 행 채우기)

- 이력 상세에서 실패한 실행의 **빠진 행 채우기** → 원 실행과 같은 조건으로 소스를 다시 읽어, 타겟에 이미 있는 키는 건너뛰고 **없는 행만** 적재합니다. 새 실행으로 남고 원 실행과 이어집니다(`parent_migration_id`). API: `GET`(확인)·`POST /api/migrate/jobs/{migrationId}/fill-missing`.
- 실패 원인(잠금·연결 장애)이 풀린 뒤에 씁니다. 데이터 문제(길이·NULL·중복)는 원인을 먼저 고치지 않으면 같은 자리에서 다시 실패합니다.
- 할 수 없는 경우(사유를 보여 줍니다): 실패(FAILED)가 아닌 실행, NORMAL 이 아닌 실행, 엑셀 이관, 타겟 PK 를 찾지 못한 테이블, **PK 에 채번 컬럼이 있는 테이블**(다시 읽으면 번호가 새로 잡힘), **원 실행 이후 소스 건수가 바뀐 경우**. 이때는 위 "다시 돌리기(전량)" 로 정리 후 재실행합니다.
- 예전 "실패 청크 재시도" 는 없어졌습니다. 적재가 여러 스레드에서 병렬로 이뤄져 청크 번호로는 무엇이 빠졌는지 알 수 없기 때문입니다.

## 추가분만 (증분)

1. Source SQL 이 기간 컬럼(예 MOD_DATE)을 `startDate/endDate` 로 바인딩해야 합니다.
2. 테이블 이관 실행에서 **기간 조건**을 켜고 마지막 이관 이후 날짜를 넣습니다. 큰 범위는 **날짜 분할**(1d/1w/1m)로 나눕니다.
3. 변경된 행도 같이 오므로 Target XML 은 UPSERT 로, `ignoreExistingData` 켜고 실행.
4. 변경 감지 컬럼이 믿을 만한지(수정일이 갱신되는지) 소스 담당자와 확인합니다. 삭제는 감지되지 않습니다(F2 삭제 표시 유지 방식이면 감지됨).

## 순서가 있는 여러 테이블

- **실행 목록**에 부모 → 자식, 코드·시퀀스 → 업무 순으로 쌓고 "목록 순서대로 실행". FAILED 가 나오면 멈춥니다. 차단·경고는 계속 진행하고 끝에 요약 알림.
- 예제 앱 순서: tb_sequence → tb_code_group → tb_code → tb_member_grade → tb_member → tb_member_login_log → tb_board → tb_post → tb_post_file → tb_post_comment → tb_stat_daily → tb_stat_menu.

## 재실행 전에 보는 것

| 확인 | 어디서 |
|---|---|
| 지금 다른 이관이 도는가 | 실행 현황 · 상단 점 |
| 적재 쿼리 방식(INSERT / UPSERT / IGNORE) | Target 매퍼 XML, 도구 DDL → Writer 로 바꿀 수 있음 |
| 채번 컬럼 여부 | 테이블 이관 실행 진행 현황의 시퀀스 요약, Strategy TableOptions |
| 마지막 실행의 건수·사유 | 이력 상세 |
